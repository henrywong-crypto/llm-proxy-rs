:toc:
:toclevels: 3

== Overview

This document describes error formats in Anthropic's Messages API v1, specifically focusing on Server-Sent Events (SSE) streaming errors.

**Key Points:**

- Errors can appear as HTTP responses (non-200) or SSE events (200 with error data)
- The API may return HTTP 200 but include error events in the stream
- All errors follow a consistent JSON structure
- `overloaded_error` is the only retryable error type

== Error Structure

=== Base Format

All errors use this structure:

[source,json]
----
{
  "type": "error",
  "error": {
    "type": "<error_type>",
    "message": "<description>",
    "details": null
  }
}
----

== Error Types & Examples

=== overloaded_error (529)

**When:** API is temporarily overloaded

**Retryable:** Yes

**HTTP Response:**
[source,http]
----
HTTP/1.1 529 Service Overloaded
Content-Type: application/json

{
  "type": "error",
  "error": {
    "type": "overloaded_error",
    "message": "Overloaded"
  }
}
----

**SSE Stream:**
[source,text]
----
event: error
data: {"type":"error","error":{"type":"overloaded_error","message":"Overloaded"}}

----

=== invalid_request_error (400)

**When:** Malformed request or invalid parameters

**Retryable:** No

[source,json]
----
{
  "type": "error",
  "error": {
    "type": "invalid_request_error",
    "message": "max_tokens: Field required"
  }
}
----

**Common Causes:**
- Missing required fields
- Invalid parameter values
- Token limits exceeded
- Malformed JSON

=== authentication_error (401)

**When:** Invalid or missing API key

**Retryable:** No

[source,json]
----
{
  "type": "error",
  "error": {
    "type": "authentication_error",
    "message": "invalid x-api-key"
  }
}
----

=== permission_error (403)

**When:** API key lacks required permissions

**Retryable:** No

[source,json]
----
{
  "type": "error",
  "error": {
    "type": "permission_error",
    "message": "Your API key does not have permission to use the specified model"
  }
}
----

=== not_found_error (404)

**When:** Resource doesn't exist

**Retryable:** No

[source,json]
----
{
  "type": "error",
  "error": {
    "type": "not_found_error",
    "message": "The requested model does not exist"
  }
}
----

=== rate_limit_error (429)

**When:** Too many requests

**Retryable:** Yes (after delay)

[source,json]
----
{
  "type": "error",
  "error": {
    "type": "rate_limit_error",
    "message": "Rate limit exceeded. Please try again later."
  }
}
----

**Response Headers:**
[source,http]
----
retry-after: 60
x-ratelimit-limit: 1000
x-ratelimit-remaining: 0
x-ratelimit-reset: 1706140800
----

=== request_too_large (413)

**When:** Request payload too large

**Retryable:** No

[source,json]
----
{
  "type": "error",
  "error": {
    "type": "request_too_large",
    "message": "Request exceeds maximum allowed size"
  }
}
----

=== internal_server_error (500)

**When:** Unexpected server error

**Retryable:** Yes

[source,json]
----
{
  "type": "error",
  "error": {
    "type": "internal_server_error",
    "message": "An internal server error occurred"
  }
}
----

== Token Limit Errors

=== Context Window Exceeded

[source,json]
----
{
  "type": "error",
  "error": {
    "type": "invalid_request_error",
    "message": "prompt is too long: 250000 tokens > 200000 maximum"
  }
}
----

**Status Code:** 400

**Model Limits:**

|===
|Model |Context Window |Max Output Tokens

|claude-3-opus-20240229
|200,000
|4,096

|claude-3-sonnet-20240229
|200,000
|4,096

|claude-3-haiku-20240307
|200,000
|4,096

|claude-3-5-sonnet-20241022
|200,000
|8,192

|claude-sonnet-4-5-20250929
|200,000
|64,000

|claude-haiku-4-5
|200,000
|64,000

=== Max Tokens Validation

When `max_tokens` exceeds model limit, the SDK clamps the value and returns a warning (not an error):

[source,json]
----
{
  "type": "warning",
  "feature": "max_tokens",
  "details": "999999 is greater than claude-haiku-4-5 64000 max output tokens. The max output tokens have been limited to 64000."
}
----

== Error Handling Patterns

=== TypeScript: Basic Retry

[source,typescript]
----
async function callWithRetry(maxRetries = 3) {
  for (let i = 0; i < maxRetries; i++) {
    try {
      return await model.doGenerate({ prompt });
    } catch (error) {
      if (error.statusCode === 529 || error.statusCode === 500) {
        const delay = Math.pow(2, i) * 1000; // Exponential backoff
        await new Promise(resolve => setTimeout(resolve, delay));
        continue;
      }
      throw error; // Non-retryable error
    }
  }
  throw new Error('Max retries exceeded');
}
----

const { stream } = await model.doStream({ prompt });

=== TypeScript: Rate Limit Handling

[source,typescript]
----
try {
  const result = await model.doGenerate({ prompt });
} catch (error) {
  if (error.statusCode === 429) {
    const retryAfter = error.responseHeaders?.['retry-after'];
    if (retryAfter) {
      await new Promise(resolve => 
        setTimeout(resolve, parseInt(retryAfter) * 1000)
      );
      // Retry...
    }
  }
}

=== Rust: Error Enum

[source,rust]
----
#[derive(Debug, thiserror::Error)]
pub enum AnthropicError {
    #[error("Overloaded: {0}")]
    Overloaded(String),
    
    #[error("Invalid request: {0}")]
    InvalidRequest(String),
    
    #[error("Authentication failed: {0}")]
    Authentication(String),
    
    #[error("Rate limit exceeded: {0}")]
    RateLimit(String),
    
    #[error("Internal server error: {0}")]
    InternalServer(String),
}

impl AnthropicError {
    pub fn is_retryable(&self) -> bool {
        matches!(
            self,
            Self::Overloaded(_) | Self::RateLimit(_) | Self::InternalServer(_)
        )
    }
    
    pub fn status_code(&self) -> u16 {
        match self {
            Self::InvalidRequest(_) => 400,
            Self::Authentication(_) => 401,
            Self::RateLimit(_) => 429,
            Self::InternalServer(_) => 500,
            Self::Overloaded(_) => 529,
        }
    }
}
----

=== Rust: Retry Logic

[source,rust]
----
use tokio::time::{sleep, Duration};

pub async fn call_with_retry<F, T>(
    mut f: F,
    max_retries: u32,
) -> Result<T, AnthropicError>
where
    F: FnMut() -> Pin<Box<dyn Future<Output = Result<T, AnthropicError>> + Send>>,
{
    let mut attempts = 0;
    
    loop {
        match f().await {
            Ok(result) => return Ok(result),
            Err(e) if e.is_retryable() && attempts < max_retries => {
                attempts += 1;
                let delay = Duration::from_secs(2u64.pow(attempts));
                sleep(delay).await;
            }
            Err(e) => return Err(e),
        }
    }
}
----

== Best Practices

1. **Always check for errors in SSE streams** - Errors can appear mid-stream
2. **Implement exponential backoff** for retryable errors (529, 429, 500)
3. **Respect `retry-after` headers** for rate limits
4. **Log error details** for debugging
5. **Handle token limits** before sending requests
6. **Validate API keys** before production deployment
7. **Monitor error rates** to detect issues early

== Bedrock Proxy Implementation

When proxying Anthropic requests through AWS Bedrock, errors must be converted to the standard Anthropic SSE format:

=== Complete Error Response

[source,text]
----
HTTP/1.1 200 OK
Content-Type: text/event-stream

event: message_start
data: {"type":"message_start","message":{"id":"msg_123","type":"message","role":"assistant","content":[],"model":"claude-3-5-sonnet-20241022","stop_reason":null,"stop_sequence":null,"usage":{"input_tokens":0,"output_tokens":0}}}

event: error
data: {"type":"error","error":{"type":"invalid_request_error","message":"The content field in the Message object at messages.303 is empty"}}

event: message_stop
data: {"type":"message_stop"}

----

**Key Requirements:**

1. Always return HTTP 200 for streaming responses
2. Send `message_start` event first
3. Send `error` event with proper error type and message
4. Send `message_stop` event to close the stream
5. Use actual Bedrock error messages for better debugging
